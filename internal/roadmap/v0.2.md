# v0.2 — The African patterns

**Goal:** the inputs that USWDS and GOV.UK do not have and every African service needs. This is the release that makes afrigov more than a re-skin.

**Target:** six weeks after 0.1. Cut scope before extending the date.

## Scope

### Components

- **Phone number** `.ag-phone`: country-code select (prefilled from the pack) plus national number field. `autocomplete="tel-national"`. Hint shows the local format.
- **National ID** `.ag-id-input`: a text input whose width, hint, `inputmode` and pattern come from the pack (`idFormats` in `$extensions`). Nigeria NIN 11 digits, Kenya ID 8 digits, Ghana card `GHA-XXXXXXXXX-X`.
- **Region selector** `.ag-region`: two selects, region then sub-region, with the list published in the pack JSON. No JS required; with JS the second select filters.
- **Currency display** `.ag-money`: symbol and formatting from the pack, tabular figures.
- **Character count** `.ag-char-count`: JS enhancement over `.ag-textarea` with `maxlength` in the hint as the no-JS state.
- **Service card** `.ag-card`: whole-card link for service listings.
- **Details** `.ag-details`: single disclosure.
- **Language switcher** `.ag-lang`.

### Packs

- Ghana (gh): red, gold, green. Gold is the derivation test case: the build must produce a usable primary from `#fcd116` and the docs must show both.
- Rwanda (rw): blue, yellow, green. Kinyarwanda, French, English strings.
- Pack schema grows: `idFormats`, `phone` (dialling code, national length, example), `currency` (code, symbol, decimals), `regions` (name of the level, list). All optional. A JSON schema file is published so packs can be validated.

### Docs

- A page per component instead of one long page, once there are more than 20. Until then, one page.
- "Build a pack" guide with the schema.

## Exit criteria

- [ ] Four packs, all passing, one of them derived.
- [ ] Pack JSON schema published and validated in tests.
- [ ] `core.min.css` still under 20 KB gzipped. Country data lives in the pack JSON, not the CSS.
- [ ] Every new component on the docs page, axe-tested.
