# v0.3 — The audit

**Goal:** a command anyone can run against any government website, and a scoreboard that gets the project talked about.

## Scope

### `afrigov audit <url>`

- `npx afrigov audit https://nimc.gov.ng` runs axe-core through Playwright against the page at phone width and desktop width.
- Output: a score and grade, the top five failures with the WCAG criterion and a one-line fix, and which afrigov component would solve each one.
- `--json` for tooling, `--all` for every rule, `--pages <sitemap>` to crawl.
- Ships as a separate package `afrigov-audit` so the design system stays dependency-free. The `afrigov` package gets a `bin` that prints "run npx afrigov-audit".

### Scoreboard

- A page in the docs: the 30 most-used government sites across the packs' countries, audited monthly by a scheduled workflow, scores over time.
- Every entry links to the audit output and to the component that fixes the top failure.
- Publish the first scoreboard as a launch post. TechCabal, Techpoint, and the a11y community have all written about this gap and will cover a number they can quote.

### Components

- File upload, password with show/hide, tabs, step indicator, notification count.
- South Africa pack (za): six colours, eleven languages. Tests the flag with more than three stripes and the language switcher.

## Exit criteria

- [ ] Audit runs against ten real sites without crashing, in under 60 seconds each.
- [ ] Scoreboard published with a methodology section that a journalist could quote.
- [ ] Five packs.

## Risks

- Government sites may block headless browsers. Retry with a real user agent and back off. Never bypass a WAF.
- Publishing scores can be read as an attack. The tone of the scoreboard is "here is the fix", never "here is the shame". Every row links to a component.
