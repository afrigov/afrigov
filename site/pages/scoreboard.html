Accessibility check

Once a month, the main public services of each country with a pack are checked with afrigov-audit. Each site's biggest problem is listed with the component that fixes it. The point is the fix.

Automated checks find about a third of real accessibility problems, so a good result here is a floor, not a pass. A poor result is a list of things to do, each with instructions. Sites are grouped by country and listed alphabetically, not ranked.

How the check works

  • Each site's home page is loaded once in a real browser at phone width (375px) and desktop width (1280px), as an anonymous visitor, with a user agent that names the tool. Nothing is bypassed; a site that blocks automated browsers is listed as not checked.
  • axe-core runs with the WCAG 2.0, 2.1 and 2.2 AA rule sets, plus five checks for problems common on government sites: language declared, zoom allowed, skip link, page title, tap targets at phone width.
  • The score starts at 100 and loses points per failing rule, weighted by severity and capped per rule so one repeated mistake does not hide the rest. The formula and weights are in the afrigov-audit README.
  • Grades: A accessible (90 and above), B nearly (75), C partly (60), D mostly not (40), F not yet (below 40).
  • Anyone can reproduce a row: npx afrigov-audit <url>.

Fixed something, or think a result is wrong?

Request a re-check. A site that improves is re-run and the page updated outside the monthly cycle. If a result is wrong, say what the page actually does and it will be corrected or the check changed. Sites to add or remove go the same way.

afrigov is an open-source project and is not affiliated with any government. The sites listed are public services chosen because people depend on them, not for any other reason.
