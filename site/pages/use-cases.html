Use cases

What afrigov looks like on a real government website, and the two tools that make it easy to adopt: a WordPress theme and an accessibility check.

Rebuilds of real websites

A use case takes a live government website and rebuilds it page for page on afrigov, installed from the CDN the way an agency would. Every gap the rebuild finds goes back into afrigov as a component or a fix. Each rebuild is unofficial and says so on every page.

  • Federal Ministry of Communications, Innovation and Digital Economy

    Nigeria · fmcide.gov.ng · 29 pages, including a multi-step application journey. Seventeen findings, which became ten components and patterns in afrigov 0.5 to 0.8.

All use cases, with the scores of the real sites beside the rebuilds. The badges are written by the audit every week, not by hand.

WordPress theme

Most government websites on the continent already run WordPress. afrigovPress is afrigov as a WordPress theme, so adopting it is a matter of installing and activating a theme, not rebuilding a site.

  • The country pack, the organisation's name and crest, the address and social accounts are site settings.
  • The official banner, header and footer are fixed templates that an editor cannot break.
  • News is a dated list with thumbnails; articles have a lead image.
  • Every page gets its title, description and structured data from what the editor already wrote.
  • Works with the block editor and the classic editor. Posts, pages, menus and media carry over from the old theme.

It carries a pinned afrigov version and updates like any other theme.

Accessibility check

afrigov-audit checks any web page from the command line, at phone and desktop widths, and says which afrigov component fixes each problem. It is what scores the rebuilds above. 

npx afrigov-audit https://example.gov.ng/
npx afrigov-audit https://example.gov.ng/ --badge badges/home.svg

With --badge it writes the grade and score as a badge, so a README or a status page shows the last audit instead of a number someone typed.
