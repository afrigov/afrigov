Find one entry in a long list

When a service lists dozens or hundreds of offices, let people narrow the list by region and by words they know. Keep the controls simple, show how many entries match, and explain what to do when none do.

When to use

Use this pattern when a page has a long list of similar entries, such as offices, service centres, clinics or public facilities. It complements pagination: filtering helps people find a specific entry; pagination helps them move through the remaining list.

Example

The example uses a region select and a text field above a table. Replace the sample entries and region names with the service's real data. The complete list remains available if JavaScript is disabled.

How it works without JavaScript

Treat the form as a normal GET form. Set its action to the service's directory route, read the region and query parameters on the server, and return the matching rows with the selected values still in the controls. With no filters, return the complete list. This keeps filtering bookmarkable, shareable and usable with assistive technology, older devices and scripts disabled.

Do not rely on a client-side script to fetch the only copy of the list. If the data is too large to render at once, provide a server-rendered filtered result and ordinary pagination.

Enhance filtering with JavaScript

If the full list is already in the page, JavaScript can filter rows as people change the controls instead of submitting the form. Keep the same form and server-side GET route as the fallback. Add a submit handler only after the script has found the controls, results table, count and empty state; if setup fails, leave the form working normally. 

const form = document.querySelector("#office-filters");
const region = form?.elements.namedItem("region");
const query = form?.elements.namedItem("q");
const rows = [...document.querySelectorAll("#office-list tbody tr")];
const count = document.querySelector("#office-count");
const empty = document.querySelector("#office-empty");

if (form && region && query && rows.length && count && empty) {
  empty.hidden = true;
  function updateResults() {
    const selectedRegion = region.value.toLocaleLowerCase();
    const words = query.value.trim().toLocaleLowerCase();
    let visible = 0;

    rows.forEach((row) => {
      const matchesRegion =
        !selectedRegion || row.cells[1].textContent.trim().toLocaleLowerCase() === selectedRegion;
      const matchesWords = !words || row.textContent.toLocaleLowerCase().includes(words);
      const show = matchesRegion && matchesWords;
      row.hidden = !show;
      if (show) visible += 1;
    });

    count.textContent = "Showing " + visible + (visible === 1 ? " office" : " offices");
    empty.hidden = visible !== 0;
  }

  region.addEventListener("change", updateResults);
  query.addEventListener("input", updateResults);
  form.addEventListener("submit", (event) => {
    event.preventDefault();
    updateResults();
  });
  updateResults();
}

In this snippet, use the form id office-filters and include the empty-state element shown below. The example is illustrative: adapt the region column and selectors to your own markup.

Keep the empty state where the table would be, and make the way back to the full list obvious. In a live implementation, the script should reveal this state only when the visible row count is zero. A server-rendered page should return the same message when the submitted filters have no matches.

Accessibility

  • Give each control a visible label. Do not use placeholder text as the only label.
  • Put the result count in a persistent element with role="status". Update it after filtering so screen readers announce the new count without moving focus.
  • Use real table captions and header scopes, or a semantic list if the information is not tabular.
  • Do not move focus when rows change. Keep keyboard focus on the control the person is using.
  • Keep the empty-state heading and recovery action in the normal reading order.
  • Do not announce every keystroke with a long list of matching names; announce the count and let people navigate the results.
